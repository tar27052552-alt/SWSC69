# ผลงานสภานักเรียนรายปี — เตรียมในเครื่อง 13 ตุลาคม 2569

## การใช้งาน

หน้า public ปรับเป็นโทนม่วง–ทองเช่นหน้าหลัก มีส่วนเปิดหน้าพร้อมภาพผลงาน/ตราปีการศึกษา วงแหวนและภาพลอยช้า ๆ แถบเลือกปี การ์ดรูปขนาดใหญ่ และหน้าอ่านรายละเอียดเข้าชุดกัน แอนิเมชันปิดตาม reduced motion และตรวจภาพหน้าจอที่ 320–1440 px รวมถึงแนวนอนแล้ว การเปลี่ยน UI นี้ไม่แก้ข้อมูลหรือสิทธิ์ backend

- ข่าวหมวด `ผลงาน` แสดงในหน้าผลงานอัตโนมัติด้วยรายการเดิม ไม่มีการคัดลอกหรือสร้างแถวใหม่ ปีการศึกษาใช้ฟิลด์ `academic_year` ถ้ามี ตามด้วยปีที่ระบุชัดเจนในหัวข้อหรือเนื้อหาข่าว (รองรับเลขไทย) โดยใช้ข้อความระบุปีการศึกษารายการแรก เมื่อไม่ระบุจึงใช้วันที่ลงข่าว (`created_at`) ตามเวลาไทย พฤษภาคม–เมษายน เปลี่ยนหมวดหรือลบข่าวจะเปลี่ยนหน้าผลงานเมื่อรีเฟรช ลิงก์รายละเอียดข่าวใช้ `id=news-<id>`
- ข่าวหมวดผลงานแสดงได้แม้ตาราง archive ยังไม่ได้ติดตั้ง ส่วนการเพิ่มผลงานรุ่นพี่ผ่านหลังบ้านยังต้องใช้ migration ตามเดิม

- หน้าสาธารณะ `/portfolios/` เปิดปีล่าสุดที่มีผลงานเผยแพร่ เลือกปีเก่าได้ และเปิดรายละเอียดผ่าน `?year=2568&id=<uuid>`
- หลังบ้าน `/admin/#/admin-portfolios` สำหรับ role `admin` เท่านั้น เพิ่มปี ชื่อรุ่น สรุป และภาพปกได้
- เพิ่มผลงานโดยเลือกปีเอง กรอกวันที่ รายละเอียด ผลสำเร็จ ฝ่าย และแนบภาพปก/ภาพเพิ่มเติม เลือกผลงานเด่น บันทึกเป็นร่าง ดูตัวอย่าง แล้วเผยแพร่ได้
- ภาพ JPG/PNG/WebP ขนาดไม่เกิน 10 MB ต่อภาพ ภาพเพิ่มเติมสูงสุด 20 ภาพ ภาพปกจำเป็นก่อนเผยแพร่
- ถอนเผยแพร่หรือเอาภาพออกจากรายการไม่ลบต้นฉบับใน Storage ลบปีได้เมื่อไม่มีผลงานอยู่เท่านั้น

## ข้อมูลและความปลอดภัย

### จัดการข่าวหมวดผลงานในหลังบ้าน

หน้าแอดมินรวมปีจากผลงานย้อนหลังและข่าวหมวดผลงาน แสดงข่าวในส่วนแยก ให้ดูตัวอย่างและไปแก้เนื้อหาที่หน้าข่าวได้ แม้ยังไม่มีตาราง archive ก็ยังอ่านข่าวส่วนนี้ได้ พร้อมข้อความบอกการตั้งค่าที่ขาด

Migration `20261013083743_portfolio_news_management.sql` (ใช้หลัง migration ผลงานรายปี) เพิ่มปีสำหรับผลงาน ตัวเลือกผลงานเด่น และซ่อนเฉพาะหน้าผลงานลงในข่าวเดิม ผ่าน RPC `manage_news_portfolio` ตรวจ admin และ trigger ป้องกันแก้ฟิลด์ตรงผ่าน API โดยบัญชีฝ่ายอื่น การเปลี่ยน metadata ไม่แก้ headline/detail/วันที่/รูป/category และไม่สร้างข่าวสำเนา ปีที่มีเฉพาะข่าวผลงานก็แสดงสรุปและภาพปกของปีที่แอดมินบันทึกได้

ทดสอบ `node tests/portfolio-news-db.mjs` บนฐานข้อมูลจำลองและ `.learning-source/portfolio-news-admin-check.mjs` ในเบราว์เซอร์กับ API จำลองผ่าน: แก้ปี/featured/hidden, ปฏิเสธสมาชิกผ่าน RPC และเขียนตรง, รูปปกปีตามสิทธิ์, ซ่อนแล้วข่าวเดิมยังอยู่ ไม่ได้ apply migration หรือทดสอบการเขียนกับ backend จริง

Migration `20261013063513_council_portfolios.sql` เพิ่มสองตารางและ private bucket `council-portfolios` เปิด RLS ทุกตาราง ใช้ helper บทบาทผู้ใช้ของระบบเดิมที่ตรวจ banned/must_change_password แล้ว ไม่ใช้ user_metadata ตัดสินสิทธิ์

สาธารณะเข้าถึงเฉพาะผลงาน published และปีที่มีผลงาน published รูปเข้าถึงได้เฉพาะเมื่อเชื่อมกับผลงานหรือปีที่เผยแพร่ ลิงก์รูปมีอายุ 5 นาที ลิงก์ที่ออกไปก่อนถอนเผยแพร่อาจยังใช้ได้จนครบอายุ และไม่สามารถเรียกคืนไฟล์ที่ผู้อื่นบันทึกไว้ได้

หน้า public ใช้ client ที่ไม่เก็บหรือรับเซสชันแอดมิน แม้เปิดในเบราว์เซอร์เดียวกันก็ไม่แสดงร่าง การบันทึกไม่ retry อัตโนมัติ เมื่อ timeout ให้รีเฟรชตรวจผลก่อนส่งใหม่ UUID ของผลงานถูกกำหนดตั้งแต่เริ่มสร้างเพื่อป้องกัน insert ซ้ำด้วย ID เดิม

## การตรวจที่ผ่านในเครื่อง

- `node tests/portfolio-db.mjs` — รัน migration จริงบน PGlite จำลอง Supabase roles/storage: อ่านเฉพาะ published, ร่างและรูปไม่เปิดต่อสาธารณะ, admin-only writes, ห้ามลบปีที่มีผลงาน, ถอน/เผยแพร่ใหม่ไม่ทำข้อมูลหรือรูปหาย
- `node --test tests/portfolio-utils.test.mjs` — ขนาดรูปต่ำกว่า/เท่ากับ/เกิน 10 MB, MIME, การเรียงเด่นก่อนแล้ววันที่, timeout และไม่มี retry
- `node tests/portfolio-browser.mjs` — API จำลองทั้งหมด ไม่ส่งคำขอเขียนไปบริการจริง: หลายปี ลิงก์ตรง ร่างไม่ปรากฏ client แยกจากแอดมิน โหลดล้มเหลว/ลองใหม่ ปีว่าง เพิ่มปี/ผลงาน/รูป 3 ไฟล์ preview ด้วย Tab/Escape เผยแพร่/ถอนเผยแพร่ ป้องกันลบปีที่มีผลงาน และผู้ใช้ member ถูกปฏิเสธ
- ตรวจ 320, 390, 768, 1440 px และมือถือแนวนอน ไม่พบ overflow หรือ JavaScript exception ในเส้นทางทดสอบ พร้อมดูภาพหน้าจอจริงจากเบราว์เซอร์
- ESLint ไฟล์ใหม่และ build ผ่าน

สคริปต์ SQL ใช้โมดูล PGlite ที่มีอยู่ใน `.learning-source/pg-runtime` หรือกำหนด `PGLITE_MODULE` สคริปต์เบราว์เซอร์กำหนด `PLAYWRIGHT_MODULE`, `CHROMIUM_PATH`, `PORTFOLIO_TEST_URL` ได้

## เปิดใช้ภายหลัง

ยังไม่ได้ใช้ migration หรือสร้างข้อมูลในระบบจริง และยังไม่ deploy เว็บ ต้องตรวจ helper สิทธิ์เดิมและ Storage policies ที่มีอยู่ก่อนใช้ migration จากนั้น deploy เว็บพร้อมเส้นทาง `/portfolios/` ไม่ต้องเปลี่ยน Apps Script หรือ Edge Functions สำหรับฟีเจอร์นี้

ต้องตรวจการอัปโหลดและ signed URL ด้วยบัญชีจริงอีกครั้งหลังอัปเดต backend ผลในเครื่องไม่ยืนยันสภาพการตั้งค่า Storage ที่ใช้งานจริง

ข้อมูลข่าวเดิม สมาชิก การเงิน เวร และคะแนนหลักสูตรไม่ถูกย้ายหรือเปลี่ยน โค้ดการแก้ระบบรอบก่อนที่อยู่ในเครื่องยังคงอยู่ ไม่มีการนำรูปหรือข้อความสมมติลงระบบจริง

## สถานะเปิด backend
ผู้ใช้อนุมัติและอัปเดต Supabase โครงการ SWSC69 แล้ว: migration council_portfolios และ portfolio_news_management สำเร็จ ตรวจ RLS, private bucket และสิทธิ์ RPC แล้ว ไม่สร้างปีหรือผลงานทดสอบในฐานข้อมูลจริง และยังไม่ deploy เว็บ
